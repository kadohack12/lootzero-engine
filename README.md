## ⚡ The Problem vs. The Solution

Most game-deal platforms mix paid games with free-to-play promotions, low-signal giveaways, and fragile HTML scrapers that are quickly blocked.

**LootZero solves this cleanly:**

- 🚫 **Zero F2P bloat:** keeps offers where a paid retail price is reduced to zero.
- 🛡️ **Backend-first ingestion:** queries structured Epic Games and CheapShark endpoints instead of depending on DOM scraping.
- 💸 **Serverless and free to run:** executes every 30 minutes on GitHub Actions with no always-on server.
- 🧠 **Persistent deduplication:** commits an atomic `claimed_games.json` cache so the same deal is not broadcast repeatedly.

## 🏗️ Architecture

```text
[ Epic Games backend ] ──┐
[ CheapShark / Steam ] ──┼──▶ [ GitHub Actions Runner ] (Cron: */30 min)
[ r/FreeGameFindings ] ──┘              │
                                        ▼
                          [ Atomic Git Cache Deduplication ]
                                        │ (New deal detected)
                   ┌────────────────────┼────────────────────┐
                   ▼                    ▼                    ▼
            [ Discord Webhook ]  [ Telegram Bot API ]  [ Make.com Webhook ]
           (Relative expiry)       (Direct push)                 │
                                                               ▼
                                                        [ Facebook Page ]
```

## ✨ Key Features

- **Epic Games Store ingest:** reads active promotional offers from Epic's structured backend endpoint.
- **Steam 100% off tracker:** uses the CheapShark deals API and keeps deals with a positive retail price.
- **Reddit fallback ingest:** monitors `r/FreeGameFindings` for Steam and Epic alerts.
- **Dynamic Discord timestamps:** embeds use Discord's relative timestamp format for expiry dates.
- **Autonomous cache persistence:** atomically saves and commits `claimed_games.json` to prevent duplicate alerts.
- **Omnichannel dispatch:** supports Discord embeds, direct Telegram Bot API messages, and Make.com routing.

## 🚀 Quickstart

### 1. Fork or clone

```bash
git clone https://github.com/kadohack12/lootzero-engine.git
cd lootzero-engine
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
```

### 2. Configure repository secrets

In **Settings → Secrets and variables → Actions**, add the values you want to use:

| Secret | Description | Required |
| :--- | :--- | :---: |
| `DISCORD_WEBHOOK_URL` | Discord channel webhook URL | Optional |
| `TELEGRAM_BOT_TOKEN` | Token generated by BotFather | Optional |
| `MAKE_WEBHOOK_URL` | Make.com custom webhook URL | Optional |

The Telegram channel is configured by `TELEGRAM_CHAT_ID` in the workflow. For local runs, you can override it with an environment variable.

### 3. Enable write permissions

In **Settings → Actions → General → Workflow permissions**, enable **Read and write permissions** so the scheduled workflow can persist the cache.

### 4. Run

The workflow runs every 30 minutes and can also be started manually from the **Actions** tab.

For a local run:

```bash
DISCORD_WEBHOOK_URL="https://discord.com/api/webhooks/..." \
TELEGRAM_BOT_TOKEN="..." \
TELEGRAM_CHAT_ID="@MyChannel" \
python main.py
```

Never commit tokens, webhook URLs, or other credentials.

## 📡 Broadcasting

| Channel | Integration | Payload |
| :--- | :--- | :--- |
| Discord | Native webhook | Embed with store, original price, link, and relative expiry |
| Telegram | Telegram Bot API | HTML-formatted message with link and expiry |
| Facebook and other destinations | Make.com webhook | Normalized JSON deal payload |

Each new deal sent to Make contains `game_id`, `title`, `store`, `original_price`, `url`, `expires_at`, `image_url`, and a human-readable `message`.
